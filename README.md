# 학사일정

구글 스프레드시트를 읽어 보여 주는 단일 HTML 파일. 빌드도 서버도 없다.

그래서 이 앱은 뷰어다. 시트를 고치는 길은 `수정 요청` 하나뿐이므로,
일정 옆의 `수정 요청` 단추를 누르면 그 날짜·부서·일정이 요청 본문에 그대로 얹힌다.
쓰기처럼 보이는 다른 기능은 두지 않는다.

## 화면

`달력` `월중 계획` `학생일정` `부서` `누가기록` `수정 요청` — 여섯 개.

## 동작

- **자료 출처** — 화면 맨 아래 접이식. 시트별 행 수·갱신 시각·실패 사유와, 읽지 못한 행을
  `연중행사계획 141행 · 날짜를 읽을 수 없습니다` 처럼 짚어 준다. 원자료 링크로 그 시트를 바로 연다.
  앱이 시트를 못 고치니, 무엇이 잘못됐는지는 알려 줘야 한다.
- **연간 보기** — 열두 달을 미니 달력으로 한 화면에. 날짜마다 건수, 달마다 합계. 눌러서 상세로.
- **주말 접기** — 달력에서 주말을 끄면 토·일 일정이 금요일 칸 아래로 모인다. 일정이 사라지지 않게.
- **검색** — 검색어가 이번 달에 없어도 `검색어가 있는 달` 줄에 달마다 몇 건인지 나온다. 눌러서 그 달로 간다.
  달력·월중 계획·학생일정에서. 빈 달만 보고 "없네" 하고 돌아서지 않게.
  일정뿐 아니라 담당(경건회·자습감독) 이름도 걸린다. 자기 이름을 치면 달력 칸에 `자습감독 ○○○` 줄이 나오고
  (평소 달력에는 담당이 안 나온다), 월중 계획에서는 그 이름이 강조된다. `자습감독 김`처럼 묶어 쳐도 된다.
- **부서 걸러 보기** — 달력·월중 계획의 부서 칩으로 켜고 끈다. 좁은 화면에서는 `부서` 단추로 칩 줄을 펼친다.
- **인쇄** — A4 한 장 미리보기(달력은 가로, 월중 계획·학생일정은 세로). 글자 크기를 자동으로 정하고 남는 세로는 행이 나눠 갖는다.
  너무 작아지면 어떤 항목을 끄면 커지는지 알려 준다. `Ctrl+P`도 같은 결과.
- **중복 제거** — 같은 행사가 연중행사계획과 학생일정에 다 적혀 있으면 하루 상세에서 한 번만 나온다.
- **사본 보관** — 마지막으로 받은 자료를 `localStorage`에 둔다. 연결이 없으면 이 사본을 보여 줘
  화면이 비지 않는다. 사본으로 보여 주는 중이면 출처 패널이
  `140행 저장본 · 연결하지 못했습니다` 처럼 밝히고, 같은 자리에서 `사본 비우기`를 할 수 있다.
  사본에는 받아 온 시트 ID도 적어 두어, 시트를 바꾸면 옛 시트의 사본은 쓰지 않는다.
- **갱신** — 5분마다 다시 받는다. 받은 표가 직전과 같으면 풀지도, 사본에 쓰지도, 화면을 다시 만들지도 않는다.
  그래서 갱신이 돌아도 칸 안에서 내려 둔 스크롤, 치던 값, 초점이 그대로다. 바뀐 시트가 있을 때만 일을 한다.
- **응답 검증** — gviz 는 권한 오류도 HTTP 200 으로 준다. `status`와 표 구조를 직접 확인하고,
  시트가 돌려준 사유(`이 문서에 접근할 권한이 없습니다`)를 그대로 보여 준다.
- **빈 날 숨김** — 월중 계획·학생일정에서 일정 없는 날을 접는다. 인쇄에는 영향이 없다.
- **단축키** — `1`–`6` 화면, `/` 검색, `←` `→` 달, `T` 오늘, `P` 인쇄, `R` 새로고침.

## 색

창체 영역(자율자치·봉사·동아리·진로)도 같은 방식으로 색을 나눈다. `CAT_TONE` 참조.

부서 19개에 색상(hue)을 하나씩 주고 계열끼리 묶었다.
기획·행정 청람 / 학생지원 자주 / 학년부 황토 / 인문교과 초록 / 자연·예체능 청록.
요소에 `--dh`(색상) `--ds`(채도)를 주면 CSS가 칩·괘선·글자색을 만든다.

> 파생 색을 `:root`에서 조립하면 안 된다. 커스텀 속성은 선언된 요소에서 값이 정해지므로
> `:root`에는 `--dh`가 없어 색이 전부 죽는다. 반드시 쓰는 자리에서 `hsl()`을 만든다.

서체는 Pretendard 하나. 웹폰트가 막히면 시스템 고딕으로 떨어진다.

## 손볼 때

`index.html` 한 파일. `<style>`은 토큰 → 조각 → 머리 → 화면별 → 인쇄 → 반응형 순,
`<script>`는 설정 → 유틸 → 상태 → 데이터 → 검색 → 그리기 → 하루 상세 → 인쇄 → 설정 → 요청 → 조작 순.

화면 조각은 `paint(el, html)`로 쓴다. 직전에 쓴 문자열과 같으면 DOM을 건드리지 않는다.
`innerHTML`을 직접 써야 하면 `painted.delete(el)`로 기억을 지워 둔다(요청 폼이 그렇게 한다).

인쇄 쪽(`.paper` CSS, `paperHTML`, `fitPaper`)은 화면 코드와 따로 논다. 인쇄본을 그대로 두려면 이 셋과
전역 `table` `th` `td` `h1` 규칙을 건드리지 않으면 된다 — 종이도 이 전역 규칙을 물려받는다.

부서를 늘리면 `DEPTS`(이름·색상·채도)만 고치면 된다.

시트나 시트 소유 계정이 바뀌면 `CONFIG`의 세 곳을 본다.

- `SHEET_ID` — 새 시트 주소 `/d/` 뒤의 값. 시트는 `링크가 있는 모든 사용자 · 보기`로 공유해 둔다.
- `SHEETS` — 탭 gid(주소 끝 `#gid=`). 시트를 사본으로 만들면 gid는 그대로다. 탭 이름(`name`)은 화면 표시용이다.
- `POST_URL` — `수정 요청`을 받는 Apps Script 웹앱 주소. 웹앱은 어느 시트의 `요청사항` 탭에 쓸지가
  스크립트 안에 정해져 있으니 새 시트에서 다시 만들어 배포하고(`배포 → 새 배포 → 웹 앱`, 실행 `나`,
  액세스 `모든 사용자`) 새 주소를 넣는다. 옛 주소를 두면 요청이 옛 시트로 간다.
